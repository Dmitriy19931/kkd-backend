# ККД — backend-модуль контроля качества данных

Минимальная реализация тестового задания на Java 17 и Spring Boot 3.

## Реализовано
- PostgreSQL и миграция Flyway.
- Иерархия подразделений, цели и ключевые результаты.
- Четыре правила: `GOAL_NO_OWNER`, `GOAL_NO_KR`, `KR_WEIGHTS_SUM`, `KR_NO_TARGET`.
- Демонстрационные данные: 24 цели, 4 подразделения и два стартовых прогона.
- `GET /api/runs` — список прогонов.
- `GET /api/kkd/summary?run_id=2&unit_id=1` — метрики и сравнение.
- `GET /api/kkd/issues?run_id=2&limit=20&offset=0` — проблемы с фильтрами.
- `POST /api/runs` — создание нового прогона с повторным запуском четырёх правил.
- Единый формат ошибок 404 и 422.
- Unit-тесты JUnit 5: проверки граничных значений правил, неактивной цели, расчёта метрики и дельты.

## Запуск
1. Скопировать `.env.example` в `.env`.
2. Выполнить из корня проекта:

   ```bash
   docker compose up --build
   ```

3. Проверить API:
   - `http://localhost:8080/api/runs`
   - `http://localhost:8080/api/kkd/summary?run_id=2&unit_id=1`
   - `http://localhost:8080/api/kkd/issues?run_id=2&limit=10&offset=0`

Для создания следующего прогона отправить `POST http://localhost:8080/api/runs`.

## Запуск тестов локально
Нужны JDK 17+, Maven и доступный PostgreSQL не требуется для unit-тестов:

```bash
mvn test
```

## Архитектура
- `api` — REST-контроллеры и обработка ошибок.
- `service` — бизнес-логика расчёта ККД, метрик и дельты.
- `db/migration` — схема БД и стартовые данные.

Правила проверяются в сервисном слое отдельно от контроллера. Результаты каждого прогона сохраняются в `kkd_issues`. Сводка агрегирует данные подразделения вместе с дочерними подразделениями.

## Миграции
Миграции выполняются автоматически при старте приложения. Для проверки повторного наката на чистой тестовой БД можно удалить тестовый volume и поднять контейнер заново:

```bash
docker compose down -v
docker compose up --build
```

Flyway Community не поддерживает автоматический откат произвольной SQL-миграции. Для проверки отката в Flyway Community используйте обратный скрипт `src/main/resources/db/rollback/U1__rollback_init.sql` на тестовой БД. Скрипт удаляет таблицы проекта и `flyway_schema_history`, поэтому после повторного старта Flyway выполнит V1 заново. Скрипт намеренно не размещён в `db/migration`, чтобы Flyway не выполнял его автоматически.

```bash
docker compose stop app
docker compose exec -T db psql -U kkd -d kkd < src/main/resources/db/rollback/U1__rollback_init.sql
docker compose start app
```

После старта проверьте `docker compose logs -f app` и запрос `GET /api/runs`. Выполняйте откат только на тестовой БД: он удаляет все данные проекта.

## Использование ИИ

Основную работу над проектом — разбор требований, принятие технических решений, сборку и запуск приложения, проверку API и базы данных, анализ тестов и проверку миграций — выполнял самостоятельно.

ИИ-ассистент использовался как вспомогательный инструмент для отдельных рутинных задач: подготовки черновых шаблонов и фрагментов кода, разбора ошибок, предложений по тестам и оформления документации.
