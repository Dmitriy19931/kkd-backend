# AI-PLAN

## Роль разработчика и использование ИИ

 Я отвечал за понимание и разбор требований задания, выбор реализуемого объёма функциональности, принятие технических решений, сборку проекта, запуск окружения, проверку работы приложения и исправление выявленных проблем.

ИИ-ассистент использовался как вспомогательный инструмент для отдельных рутинных задач. Делегировал ему подготовку черновых вариантов и шаблонов, помощь с отдельными фрагментами кода и SQL, пояснение ошибок и предложения по документации. Предложения ИИ не принимались автоматически: я изучал результат, адаптировал его под проект, интегрировал и проверял работоспособность.

## Что делал самостоятельно

1. Разобрал требования задания и определил, какие функции должны войти в минимальную реализацию.
2. Определил структуру предметной области: подразделения, цели, ключевые результаты, правила контроля, прогоны и найденные проблемы.
3. Принимал решения о составе реализуемых правил ККД и ожидаемом поведении API.
4. Собирал и запускал проект, настраивал Docker Compose и подключение PostgreSQL.
5. Проверял работу REST API, анализировал ответы и проверял обработку некорректных параметров.
6. Проверял содержимое базы данных, наличие таблиц и демонстрационных записей.
7. Выполнил проверку сценария миграции, ручного отката и повторного применения миграции Flyway.
8. Запускал автоматические тесты Maven/JUnit и анализировал результаты.
9. Проверял итоговую структуру проекта и готовил README с инструкциями по запуску и проверке.

## Для каких задач использовал ИИ

- Получение черновых вариантов типового кода и конфигурации Spring Boot, Maven и Docker Compose.
- Подготовка отдельных SQL- и Java-фрагментов как отправной точки для реализации.
- Разбор сообщений компилятора, логов приложения и ошибок при запуске.
- Предложения по тестовым сценариям и проверкам граничных случаев.
- Подготовка и редактирование технической документации.

## Как контролировал результат

 Запускал команды и приложение в своей среде, проверял фактические ответы API, состояние PostgreSQL, результаты тестов и повторное применение миграции. Решения о том, какие изменения оставить, принимал я.

В частности, проверены:
- запуск приложения и PostgreSQL через Docker Compose;
- применение миграции Flyway;
- наличие демонстрационных данных;
- получение списка прогонов, сводной статистики и списка проблем через API;
- ответы API с кодами 404 и 422 для ошибочных запросов;
- прохождение автоматических тестов;
- сценарий ручного отката и повторного применения миграции.
